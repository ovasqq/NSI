# NELL и DBLP. Протокол обучения и поиска

## NELL

Скрипт сам скачивает архив Planetoid из CMU по HTTPS, проверяет SHA-256 и читает только необходимую смежность и метки. Итоговый граф содержит 65 755 вершин и 125 775 неориентированных рёбер. В исходных строках найдено 105 наблюдаемых классов. 55 864 вершины без метки получают отдельный класс unknown, поэтому модель видит 106 меток. Разметка статьи NeuGN для этих вершин не подтверждена.

По умолчанию запускаются 300 эпох NeuGN, четыре слоя, ширина 256, батч 128, подграфы на 5–19 вершин. Скрипт сохраняет модель, Adam и scheduler после каждой эпохи в checkpoints/nell_planetoid/RUN/model.pt. В журнале CUDA присутствует пиковая зарезервированная PyTorch память за эпоху. Используйте GPU с достаточной свободной памятью. В поле GPU передаётся индекс из nvidia-smi.

```bash
GPU=2 EPOCHS=300 RUN=nell_300_seed19 bash experiments/launch_nell_suite.sh
```

Чтобы сначала оценить скорость, запустите с `PHASE=train EPOCHS=10`, затем с тем же RUN повторите полную команду с `EPOCHS=300`. Скрипт продолжит обучение. Для теста ранее сохранённой эпохи используйте `PHASE=eval`. Не используйте диагностический RUN для полного обучения после переопределения STEPS_PER_EPOCH или BATCH.

Семь режимов используют 180 отложенных запросов на 16, 24 и 32 вершины, два повтора, до 30 000 шагов и 1 секунды на первое вложение. На 32 вершинах добавляется отдельное перечисление за 1 секунду без ограничения по шагам. Глубина ранжирования NeuGN в этом измерении равна 16, вычислительная реализация отличается от C++/LibTorch в статье.

1. Динамический DFS.
2. Структурная MLP.
3. Динамический DFS с резервом структурной MLP и ручной тройкой.
4. NeuGN.
5. NeuGN с ручной тройкой.
6. NeuGN с обученным селектором фиксированной тройки.
7. NeuGN с обученным селектором множества переменного размера.

В пунктах 4–7 используются одни и те же замороженные веса NeuGN. Селекторы учатся на трассах NeuGN по свидетельствам и по экономии времени. Все проверки троек и произвольных множеств используют один точный CPU-алгоритм с лимитом. Скрипт сохраняет веса селекторов, решения, FMS, счётчики проверок и MPS. Для окна перечисления подготовка запроса входит в секунду.

## DBLP

Здесь шесть режимов без трансформера: NLF/GQL с порядком кандидатов по ID, динамический DFS, динамический DFS с AC-3, структурная MLP, та же MLP с тройкой и динамический DFS с резервом MLP с тройкой. Одна лёгкая MLP обучается шесть эпох на 48 запросах. Тест использует 200 новых запросов размера 32, по 100 на плотность. Для каждого режима сначала измеряется 1 с чистого перечисления. Опциональный второй проход включает подготовку запроса в секунду. Общее время ограниченных окон на полный проход — до 20 минут плюс подготовка и обучение. Резерв включается только до первого вложения, поэтому между двумя фазами не дублируются найденные вложения.

```bash
dblp_run=$(mktemp -d experiments/results/dblp_throughput_XXXXXXXX)
caffeinate -i bash -c '
  set -e
  export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
  .venv/bin/python -u -m queries.generate --graph dblp_proxy15 --sizes 32 \
    --count 132 --seed 19 --output-dir "$1/queries"
  .venv/bin/python -u -m experiments.dblp_throughput \
    --query-dir "$1/queries" --out "$1/results" --include-setup
' _ "$dblp_run" 2>&1 | tee "$dblp_run/run.log"
```

Дополнительный проход с подготовкой даёт ещё до 20 минут ограниченных окон. Итоговый файл results.json содержит MPS по выделенному бюджету и по фактически затраченному времени, покрытие, медиану времени до первого вложения с подготовкой. Локальная версия DBLP назначает 15 синтетических меток.
