# models/ — модель NeuGN

Реплика архитектуры из статьи NeuGN (AAAI 2026): QSExtractor (GCN над запросом) + GGNavigator (двунаправленный Transformer над эйлеровой последовательностью запроса). Модель выдаёт распределение по **всем** вершинам G для текущей вершины запроса; при поиске этим распределением сортируются локальные кандидаты.

## Файлы

### [encoding.py](encoding.py) — формат входа (единственный источник правды)

Переводит *состояние поиска* (запрос Q, его эйлерова последовательность, частичное отображение, текущая вершина) в массивы токенов. Этим же кодом пользуются обучение ([train/dataset.py](../train/dataset.py)) и инференс ([hook.py](hook.py)), поэтому формат входа на обучении и при поиске не может разойтись.

- `NUM_QVERT = 64` — N в циклическом сдвиге номеров вершин Q: i' = (i + r) mod 64.
- `pad_id(num_g) = num_g`, `cls_id(num_g) = num_g + 1` — служебные токены содержимого. Словарь содержимого: id вершин G `0..num_g−1`, затем PAD и CLS.
- `gcn_adjacency(q)` — нормированная матрица смежности Â = D^{-1/2}(A + I)D^{-1/2} (Kipf & Welling), `float32`, n×n.
- `encode_query(q, seq)` — части входа, не зависящие от отображения: `seq`, `tok_label` (метка вершины в каждой позиции), `q_labels`, `q_adj`. Считается один раз на запрос.
- `encode_state(qenc, mapping, target, shift, num_g)` — добавляет:
  - `content[j]` для w = seq[j]: id образа `mapping[w]`, если w сопоставлена; **CLS** на *всех* вхождениях `target`; иначе **PAD**;
  - `qvert[j] = (w + shift) mod 64`.
- `collate(states, targets=None)` — паддинг в батч:
  - тензоры токенов `content`, `qvert`, `tok_label`, `tok_mask` (B×L, `True` = настоящий токен);
  - тензоры запроса `q_labels`, `q_adj`, `q_mask` (B×n и B×n×n);
  - `target` (B), если переданы ответы.

### [neugn.py](neugn.py) — сама сеть

- **`NeuGNConfig`** — все гиперпараметры (сохраняется в чекпойнт и восстанавливается при загрузке):
  - `num_g` — |V(G)|, размер словаря id и выходного слоя (трансдуктивность: модель привязана к одному G);
  - `num_labels`;
  - `d=256`, `layers=2` (статья: 2 для Hamster/LastFM, 4 для остальных), `heads=8`, `ffn=1024` — как в статье;
  - `gcn_layers=2`, `dropout=0.1`, `max_len=512` — в статье не указаны, см. [DECISIONS.md](../DECISIONS.md);
  - `token_labels=True` — добавлять ли эмбеддинг метки к каждому токену (наше решение, отключаемо);
  - `use_gcn=True` — `False` даёт абляцию «без GCN» из статьи.
- **`QSExtractor`**: эмбеддинг меток → `gcn_layers` слоёв `H ← Â·(H W)` с ReLU между слоями (после последнего ReLU нет) → max-pooling по настоящим вершинам → `h_Q` (B×d).
- **`NeuGN`**:
  - эмбеддинги: `content_emb` ((num_g + 2)×d), `qvert_emb` (64×d), `pos_emb` ((max_len + 2)×d, обучаемый, как в BERT), `label_emb` (опционально), обучаемый вектор-якорь `anchor`; `no_query` подставляется вместо h_Q при `use_gcn=False`;
  - вход Transformer'а: `[h_Q] [anchor] tok_1 … tok_L`, где tok = content + qvert (+ label); ко всей последовательности прибавляется позиционный эмбеддинг, затем LayerNorm;
  - `nn.TransformerEncoder` без каузальной маски (двунаправленный), GELU, padding-маска из `tok_mask`;
  - выход: скрытое состояние якоря → `Linear(d, num_g)` → логиты по всем вершинам G (softmax — внутри cross-entropy).
  - `query_vector(batch)` — отдельно считает h_Q, чтобы при поиске делать это один раз на запрос; `forward(batch, h_q=None)` принимает готовый h_Q.

### [hook.py](hook.py) — NeuGN внутри перебора

- **`NeuGNReorder(model, q, max_depth=10, device="cpu", shift=0)`** — объект-хук для `search.enumerate.enumerate_matches`, создаётся на каждый запрос:
  - в конструкторе один раз строит эйлерову последовательность Q (от вершины 0, детерминированно), кодирует запрос и считает h_Q;
  - `__call__(depth, u, mapping, cands)`: на глубинах `depth < max_depth` кодирует текущее состояние (u = CLS), прогоняет модель и сортирует кандидатов по убыванию логита «u ↦ v»; при равных логитах сохраняет порядок по id (стабильная сортировка). На глубинах ≥ max_depth возвращает кандидатов без изменений (порядок бейзлайна);
  - `scores(mapping, u, cands)` — логиты кандидатов (для тестов и анализа);
  - счётчики `calls` и `seconds` — число вызовов модели и время инференса; `experiments/fms.py` пишет их в результаты, чтобы оценить накладные расходы.
- Хук только переставляет кандидатов, и перебор это проверяет, поэтому полнота не нарушается. Тест: `test_hook_preserves_completeness`.
- Инференс одного состояния: около 1.3 мс на CPU и 2.6 мс на MPS (батч из одного элемента), поэтому по умолчанию CPU.

### [pc_hook.py](pc_hook.py) — ранжирование по p/c (наша идея 1, без дообучения)

- Теория (Simon & Kadane 1975): чтобы в среднем быстрее найти первое решение, кандидатов нужно перебирать по убыванию pᵢ/cᵢ, где pᵢ — вероятность решения в поддереве, cᵢ — стоимость его обхода.
- **`PCReorder(space, neugn=None, pc_depth=3, probes=4, alpha=1.0, seed=0)`** — хук:
  - на глубинах `< pc_depth`: score = log p̂ − α·log ĉ, сортировка по убыванию (при равенстве — по id), где
    - **p̂** — вероятности NeuGN, перенормированные softmax'ом по локальным кандидатам;
    - **ĉ** — оценка Кнута размера поддерева после u ↦ v (`probes` спусков на кандидата);
  - на глубинах `pc_depth … max_depth−1` — обычный порядок NeuGN; глубже — порядок бейзлайна;
  - при `neugn=None` — вариант «только 1/c» (без модели): сначала кандидаты с наименьшим оценённым поддеревом;
  - `probe_steps` — сколько шагов потрачено на спуски (добавляется к FMS в `experiments/fms.py`); `calls` — сколько раз считался p/c.
- Перебор проверяет, что хук только переставляет кандидатов; полнота сохраняется (тест `test_pc_hook_preserves_completeness`).
