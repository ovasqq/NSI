# train/ — обучение NeuGN

Самообучение без решателя, как в статье: обучающие «запросы» вырезаются из G случайным блужданием, правильный ответ известен — это сами вершины блуждания.

## Файлы

### [dataset.py](dataset.py) — генерация обучающих примеров на лету

- **`component_sizes(g)`** — размер компоненты связности для каждой вершины.
- **`make_example(g, start, comp_size, rng, min_size=5, max_size=19, walk_retries=10)`** — один пример:
  1. размер s ~ U{min_size … min(max_size, |компонента|)};
  2. случайное блуждание из `start` до s различных вершин (до 10 попыток, иначе `None`);
  3. индуцированный подграф = запрос Q;
  4. эйлерова последовательность из случайной стартовой вершины; сдвиг r ~ U{0…63};
  5. k ~ U{1…s} скрытых вершин, выбранных равновероятно; одна из них — цель (CLS), остальные скрытые — PAD, открытые несут свой настоящий id в G. При k = s ничего не сопоставлено — это аналог корня поиска (глубина 0);
  6. возвращает `(encode_state(...), id цели в G)`.
- **`TrainingStream(g, seed, start_epoch=0, min_size, max_size)`** — бесконечный `IterableDataset`:
  - одна эпоха = по одному примеру из каждой допустимой стартовой вершины в случайном порядке (перестановка своя для каждой эпохи, одинаковая во всех воркерах);
  - вершины делятся между воркерами DataLoader по шагу (`perm[wid::nw]`), ГСЧ воркера зависит от (seed, epoch, wid), поэтому всё воспроизводимо;
  - допустимые стартовые вершины — те, чья компонента не меньше `min_size` (на Hamster это 2 116 из 2 421: в графе 148 компонент);
  - `steps_per_epoch(batch)` — сколько батчей цикл обучения считает эпохой. Поток бесконечный, поэтому батч на стыке эпох может содержать примеры из двух соседних эпох.
- **`collate_examples(items)`** — `collate` из `models/encoding.py` для пар (состояние, ответ). Функция задана на уровне модуля: на macOS воркеры запускаются через spawn, и лямбду туда передать нельзя.

### [train_neugn.py](train_neugn.py) — CLI обучения

```bash
.venv/bin/python -m train.train_neugn --graph hamster --run paper \
    [--epochs 1000] [--batch 128] [--lr 5e-4] [--gamma 0.999] \
    [--d 256] [--layers 2] [--heads 8] [--ffn 1024] [--gcn-layers 2] [--dropout 0.1] \
    [--no-token-labels] [--no-gcn] [--min-size 5] [--max-size 19] \
    [--workers 8] [--device auto|cpu|mps|cuda] [--seed 0] [--save-every 10] [--resume]
```

- Оптимизатор Adam, `ExponentialLR(γ)` — шаг **раз в эпоху** (за 1000 эпох lr падает в e раз); потеря — cross-entropy по всем вершинам G.
- В лог каждой эпохи пишутся loss, top-1 и top-10 (доля примеров, где истинная вершина среди 10 лучших из всех |V(G)|), lr и время.
- `--no-gcn` — абляция «без GCN» из статьи.
- Выход: `checkpoints/<graph>/<run>/`:
  - `config.json` — конфиг модели и все аргументы;
  - `log.jsonl` — строка на эпоху;
  - `model.pt` — веса, состояние оптимизатора и планировщика, номер эпохи. Сохраняется каждые `--save-every` эпох атомарно (через `.tmp`), поэтому `--resume` безопасен даже после прерывания (удобно на кластере).
- **`pick_device`** — cuda → mps → cpu. **`load_model(path, device)`** — загрузка обученной модели в режиме `eval` (используется в `experiments/fms.py --method neugn`).
- Скорость на этой машине (MPS): около 3.3 с на эпоху Hamster (17 батчей), то есть около часа на 1000 эпох. Шаг на MPS в ~3.4 раза быстрее, чем на CPU.
