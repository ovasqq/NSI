# Решения, не зафиксированные в статье NeuGN

Каждая запись: что выбрали, почему, где в коде.

## Данные

- **Hamster** = KONECT `petster-hamster` (Hamsterster full). Метка вершины — атрибут `species` (16 значений). Оставлены только 2 421 вершина, у которых есть строка метаданных в `ent.petster-hamster`; из 2 426 вершин рёбер 5 метаданных не имеют. Получается ровно 2 421 / 16 621 / 16, как в статье. Порядок `names` меток — лексикографический. [data/loaders.py](data/loaders.py)
- **LastFM** = SNAP `lastfm_asia`, метка — `target` (страна, 18 классов). 7 624 / 27 806 / 18 — совпадает без обработки.
- Петли удаляются, кратные рёбра склеиваются (на этих двух графах ни того ни другого нет).

## Поиск (этап 1)

- **Шаг** = одна попытка расширения (u, v) в цикле по C_M(u), т.е. один некорневой узел дерева поиска. Шаг, завершающий вложение, считается. Уже занятые вершины G исключаются из C_M(u) заранее и шагами не считаются. FMS = номер шага, на котором найдено первое вложение. [search/enumerate.py](search/enumerate.py)
- **Фильтр по умолчанию:** LDF + NLF. GQL-фильтр (локальное отсечение + глобальное уточнение через паросочетания) пока не реализован.
- **Порядок по умолчанию:** GQL-подобный (argmin |C(u)| среди соседей уже выбранных; при равенстве — большая степень в Q, затем меньший id). Есть RI-подобный (структурный).
- **C_M(u):** перебор соседей образа той обратной соседки, чей образ имеет наименьшую степень в G; проверка принадлежности C(u) и смежности с остальными образами. Без хука порядок — по возрастанию id.
- **Хук переупорядочивания** получает (глубина, u, mapping, C_M(u)), обязан вернуть перестановку; это проверяется на каждом вызове (`validate=True`), так что отсечь что-либо хук не может.

## Запросы и замер (этап 2)

- **Запрос** = подграф G, индуцированный различными вершинами простого случайного блуждания из равновероятной стартовой вершины. Блуждание обрывается после 100·size ходов (тогда попытка отбрасывается). [queries/random_walk.py](queries/random_walk.py)
- **Dense / sparse** — порог средней степени 3 (из статьи); нужная плотность набирается отбором с отклонением. На Hamster и LastFM все наборы (8/16/20/24/32 × dense/sparse) собрались полностью по 200 запросов.
- **Набор фиксирован**: все методы оцениваются на одних и тех же JSON-файлах в `data/queries/`.
- **Эйлерова сериализация:** `networkx.eulerize`, затем эйлеров *цикл* (замкнутый, первый токен = последний), а не путь. Старт — случайная вершина на каждом обучающем примере. [queries/euler.py](queries/euler.py)
- **Бюджет FMS** — 10⁶ шагов на запрос. Не найденные за бюджет запросы цензурированы и при подсчёте медианы считаются +∞; медиана точна, пока таких меньше половины. В статье бюджет для FMS не указан. [experiments/fms.py](experiments/fms.py)
- Дополнительный sanity-бейзлайн: случайная перестановка кандидатов на каждой глубине.

## Модель и обучение NeuGN (этап 3)

Из статьи взяты: d = 256, 2 слоя Transformer (Hamster/LastFM), 8 голов, FFN 1024, Adam, lr 5·10⁻⁴, γ = 0.999, 1000 эпох, batch 128, размер обучающих подграфов 5–19, N = 64 в циклическом сдвиге. Остальное выбрано нами:

| Что | Выбор | Почему |
|---|---|---|
| k — число скрытых вершин | k ~ U{1…s}, скрытые выбираются равновероятно, цель — одна из скрытых | Покрывает все глубины поиска; k = s — аналог корня (глубина 0), где по статье основной выигрыш |
| Слои GCN | 2, ReLU между слоями, Â = D^{-1/2}(A+I)D^{-1/2}, max-pooling | Стандартный GCN; в статье число не указано |
| Метки в токенах Transformer | **да** (эмбеддинг метки прибавляется к каждому токену), флаг `--no-token-labels` | Дёшево; помогает PAD-позициям. Отключаемо, чтобы проверить влияние |
| Стартовая вершина эйлерова цикла | обучение — случайная; поиск — вершина 0 | Случайность на обучении — аугментация; при поиске нужен детерминизм |
| Сдвиг r при поиске | 0 | Все 64 значения видны на обучении, выбор не важен |
| Позиционный эмбеддинг | обучаемый, max_len = 512 | BERT-style по статье; самая длинная последовательность в тестовых наборах — 241 |
| Dropout | 0.1 | Стандарт для Transformer |
| Активация, нормализация | GELU, post-norm (`nn.TransformerEncoderLayer`), LayerNorm на входе | BERT-style |
| Шаг γ | раз в эпоху | При шаге за батч lr за 17 000+ шагов упал бы практически до нуля |
| Компоненты < 5 вершин | не используются как стартовые (Hamster: 305 вершин) | Блуждание не наберёт 5 различных вершин |
| Батч на границе эпох | может содержать примеры двух соседних эпох (бесконечный поток, 8 воркеров) | Позволяет держать воркеры живыми; на распределение примеров не влияет |
| Инференс при поиске | один прогон модели на узел поиска глубины < 10, кандидаты ранжируются по логитам выходного слоя (softmax монотонен); при равенстве — по id | Вероятности из softmax по всем V(G) дают тот же порядок, что и логиты |
| «До глубины 10» | глубины 0…9 (`--max-depth 10`) | Ровно 10 уровней |
| Устройство инференса | CPU | 1.3 мс на состояние против 2.6 мс на MPS при батче 1 |

## Ранжирование p/c без дообучения (часть 3)

| Что | Выбор | Почему |
|---|---|---|
| p̂ | softmax логитов NeuGN по локальным кандидатам | Единственный доступный без обучения прокси «решение в поддереве» |
| ĉ | оценка Кнута, 4 спуска на кандидата, лог-шкала | Классическая оценка размера дерева; лог — из-за огромного разброса |
| Где применяется | только глубина 0 (`--pc-depth 1`), ниже — NeuGN | Лучшая настройка на валидации по числу решённых |
| α | 0.25 | То же; сетка {0.25, 0.5, 1} × глубины {0, 0–2} |
| Подбор гиперпараметров | на отдельных валидационных наборах (`data/queries/hamster_val/`, 40 запросов, другой сид, бюджет 2·10⁵) | Не подгонять под тестовые запросы |
| Учёт спусков | каждый уровень спуска = 1 шаг; `fms_with_probes` = FMS + шаги спусков; бюджет ограничивает только шаги перебора, а запрос, у которого сумма > бюджета, считается цензурированным в метрике «со спусками» | Вычисление C_M на уровне спуска — та же работа, что шаг перебора |

## Оракульный эксперимент (этап 4)

| Что | Выбор | Почему |
|---|---|---|
| Истинные p, c | p = `has_solution` ∈ {0,1} (ведёт ли кандидат к вложению); c = `subtree_size` (число узлов поддерева, сам узел = 1) | Это «истинные» величины правила Simon–Kadane; вычисляются одним полным перебором |
| Порядковая инвариантность меток | метки не зависят от порядка кандидатов (дерево то же) | тот же аргумент, что и полнота перестановки; проверено тестом |
| Глубина оракула | `oracle_depth = 3` (глубины 0–2) | верхние уровни дают основной вклад; сравнение консервативно в пользу NeuGN (он работает до глубины 9) |
| Декомпозиция | `oracle_p` (−p, id), `oracle_1c` (c, id), `oracle_pc` (−p, c, id) | раздельно измерить вклад p и c |
| Размеры запросов | 8 и 10 (на 12+ полный перебор почти всегда выходит за бюджет) | баланс между «полный перебор осуществим» и «есть запас для переупорядочивания» |
| Бюджет разметки | 5·10⁶ узлов; не уложившиеся запросы цензурируются | тяжёлый хвост размера дерева; полный перебор дорог |
| Сравнение | все 5 методов на одних и тех же запросах; цензурированная медиана FMS + попарно ср. геом. отношения | как в остальных экспериментах |
| Запросы | свежий набор `data/queries/hamster/oracle_size<N>_<density>.json`, отдельный сид (база 12345) | не пересекаться с оценочными наборами |
