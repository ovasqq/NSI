# search/ — классический точный поиск подграфов

Реализует три стадии точного алгоритма (фильтр → порядок → перебор). Единственная точка, куда встраивается обучение, — **хук переупорядочивания** в `enumerate.py`. Фильтр и порядок для всех методов одинаковые, поэтому сравнение методов честное.

## Файлы

### [graph.py](graph.py) — класс `Graph`

Один класс и для графа данных G, и для запроса Q. Вершины — `0..n−1`.

Поля:
- `labels: np.ndarray[int64]` — метка каждой вершины;
- `adj: list[np.ndarray]` — **отсортированные** списки соседей. Отсортированность важна: благодаря ей локальные кандидаты без хука идут по возрастанию id (это и есть порядок бейзлайна);
- `adj_set: list[frozenset]` — те же соседи для проверки смежности за O(1);
- `degree: np.ndarray` — степени;
- `by_label: dict[label, np.ndarray]` — вершины каждой метки (для фильтра);
- `_nlf` — лениво считаемый кэш NLF-профилей.

Методы:
- `n`, `m`, `num_labels` — размеры;
- `neighbor_label_counts(v) -> Counter` — сколько соседей v имеют каждую метку (NLF-профиль); на G считается один раз для всех вершин и кэшируется;
- `has_edge(a, b)`, `edges()` — рёбра (каждое один раз, a < b);
- `from_edges(n, edges, labels)` — конструктор: петли выбрасывает, повторные и обратные рёбра склеивает;
- `from_networkx(g)` / `to_networkx()` — конвертация (нужна для тестов и эйлеризации); метка хранится в атрибуте `"label"`;
- `induced_subgraph(vertices)` — индуцированный подграф; вершина i результата = `vertices[i]`. На нём построена генерация запросов.

### [filter.py](filter.py) — множества кандидатов C(u)

Обе функции принимают `(q, g)` и возвращают список `cand`, где `cand[u]` — отсортированный `np.ndarray` вершин G. Обе **корректны** (не теряют настоящих вложений), это проверяется в тестах.

- **`ldf_filter`** — Label & Degree Filter: та же метка и `deg_G(v) ≥ deg_Q(u)`.
- **`nlf_filter`** (по умолчанию) — LDF плюс Neighbour Label Frequency: для каждой метки l у v не меньше l-соседей, чем у u.
- **`FILTERS`** — реестр `{"ldf", "nlf"}` для CLI и тестов.

### [order.py](order.py) — порядок сопоставления φ

Принимают `(q, cand)`, возвращают перестановку вершин Q. Для связного Q у каждой вершины, кроме первой, есть хотя бы одна более ранняя соседка (*обратная соседка*). Для несвязного Q функции бросают `ValueError`.

- **`gql_order`** (по умолчанию) — как в GQL (Sun & Luo 2020): старт с вершины с наименьшим |C(u)|, дальше среди соседей уже выбранных берётся вершина с наименьшим |C(u)|. При равенстве — большая степень в Q, затем меньший id.
- **`ri_order`** — как в RI (Bonnici et al. 2013), только по структуре Q: старт с вершины наибольшей степени, дальше — вершина с наибольшим числом обратных соседей. При равенстве — больше «соседей обратных соседей», затем степень, затем id.
- **`ORDERS`** — реестр `{"gql", "ri"}`.

### [enumerate.py](enumerate.py) — перебор с возвратом

**`SearchSpace(q, g, cand, order)`** — неизменяемая часть поиска: запрос, граф, кандидаты, порядок, обратные соседи каждой позиции. Метод `local_candidates(i, mapping, used)` вычисляет C_M(φ(i)) для *любого* состояния. Им пользуются и перебор, и хуки, которые заглядывают вперёд (спуски Кнута), поэтому C_M везде считается одинаково.

Главная функция:

```python
enumerate_matches(q, g, cand, order, reorder=None, *,
                  max_matches=None, max_steps=None,
                  store_embeddings=False, validate=True) -> SearchResult
```

- **Локальные кандидаты C_M(u)** (`SearchSpace.local_candidates`): для u = φ(i), i > 0, берутся образы всех обратных соседей u; перебираются соседи того образа, у которого наименьшая степень в G (*pivot*); остаются те v, что лежат в C(u), ещё не заняты и смежны со всеми остальными образами. Для i = 0 C_M(u) = C(u) без занятых вершин.
- **Шаг** = одна итерация цикла по C_M(u), т.е. попытка расширить отображение парой (u, v), т.е. один некорневой узел дерева поиска. Шаг, на котором вложение завершается, считается. Это определение используется для FMS и всех бюджетов в проекте.
- **Хук** `reorder(depth, u, mapping, candidates) -> Sequence[int]`:
  - `depth` — позиция i в φ (0 — корень);
  - `u` — текущая вершина Q;
  - `mapping[w]` — образ вершины w запроса или −1;
  - `candidates` — C_M(u) по возрастанию id.

  Хук должен вернуть **перестановку** кандидатов. При `validate=True` (по умолчанию) это проверяется на каждом вызове, и при нарушении бросается `ValueError`, поэтому модель физически не может отсечь ветку (полнота сохраняется). Хук не вызывается, если кандидатов ≤ 1.
- **Остановка:** `max_matches` — после k-го вложения; `max_steps` — перед тем как сделать шаг сверх бюджета. Реализована через внутреннее исключение `_Stop`.
- **`SearchResult`**:
  - `num_matches`, `steps`;
  - `match_steps[j]` — номер шага, на котором найдено (j+1)-е вложение;
  - `first_match_step` — то же для первого вложения (= FMS одного запроса, `None`, если вложений не найдено);
  - `embeddings` — сами вложения, если `store_embeddings=True`; кортеж индексируется вершинами Q;
  - `complete` — обойдено ли всё дерево (ни один лимит не сработал).

### [knuth.py](knuth.py) — оценка размера поддерева по Кнуту

- **`knuth_estimate(space, i, mapping, used, rng, probes) -> (estimate, probe_steps)`** — оценка числа узлов поддерева текущего узла (сам узел считается за 1), у которого следующая заполняемая позиция φ — `i`.
  - Один *спуск* (probe): на каждом уровне считается C_M, берётся случайный кандидат; при ветвлениях d₁, d₂, … оценка равна 1 + d₁ + d₁d₂ + … Она несмещённая (Knuth 1975), но с огромной дисперсией, поэтому её усредняют по `probes` спускам и используют в лог-шкале.
  - Каждый уровень спуска стоит примерно как шаг перебора и учитывается в `probe_steps`; эти шаги добавляются к FMS при честном подсчёте.
  - `mapping` и `used` после вызова восстанавливаются.
- Используется в [models/pc_hook.py](../models/pc_hook.py).
